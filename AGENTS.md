# Record Display - Chrome Extension Development Guide

**Project Type:** Chrome Extension (Manifest V3) | React 19 + TypeScript + Vite + Tailwind CSS

## Quick Start Commands

```bash
pnpm dev          # Start dev server (localhost:5173)
pnpm build        # Build extension: tsc + vite build → dist/
pnpm lint         # ESLint check
pnpm preview      # Preview production build
```

## Architecture Overview

### Extension Structure
- **manifest.json**: MV3 configuration (defines popup at `dist/index.html`)
- **src/main.tsx**: React root entry point
- **src/App.tsx**: Main app shell with page routing (Record, Settings)
- **src/pages/**: Feature pages (Record.tsx, Settings.tsx)
- **src/components/**: Reusable UI components (Button.tsx)
- **dist/**: Built extension output (generated by `pnpm build`)

### Pages
1. **Record**: Screen/tab capture using `getDisplayMedia()` API
2. **Settings**: Microphone and camera device selection using `getUserMedia()`

## Critical Details for Development

### 1. Vite Configuration with Extension
**Why it matters:** Extensions require relative asset paths in the built HTML.

- ✅ Config has `base: './'` in `vite.config.ts` — **DO NOT REMOVE**
- This ensures `dist/index.html` references assets as `./assets/...` instead of `/assets/...`
- Without this, extension popup appears blank (assets fail to load)

### 2. Plugin Stack
- **React Compiler** enabled (via `@vitejs/plugin-react`) — impacts build performance
- **Tailwind CSS** via `@tailwindcss/vite` plugin
- **Babel** via `@rolldown/plugin-babel` for React Compiler presets
- ESLint configured for React + TypeScript

### 3. Media APIs (Microphone, Camera, Screen Capture)
- Settings page uses `navigator.mediaDevices.enumerateDevices()` and `getUserMedia()`
- Record page uses `getDisplayMedia()` with custom options (browser surface, system audio, etc.)
- MediaStream lifecycle: refs used to store streams, cleanup in useEffect dependencies
- **Note:** Camera selection dropdown is defined but camera device selection logic not fully implemented yet

### 4. TypeScript & Types
- tsconfig.json uses `strict: true` (strict type checking enabled)
- React 19 types: `React.ReactElement` used in App.tsx for page components
- MediaDeviceInfo array properly typed for device lists

## Common Pitfalls & How to Avoid Them

| Issue | Cause | Solution |
|-------|-------|----------|
| **Extension popup is blank** | Vite generating absolute asset paths | Verify `base: './'` in vite.config.ts; rebuild with `pnpm build` |
| **Media device permissions denied** | User declined in permission prompt | Handle error gracefully in catch blocks; use try-catch (already in place) |
| **Selected camera not streaming** | `selectMicrophoneDevice()` called but camera logic incomplete | Camera selection is wired but missing stream assignment logic |
| **pnpm dependency conflicts** | Virtual store mismatch | Run `pnpm install` before adding deps; use `pnpm add -D [pkg]` not npm |
| **TypeScript errors on main.tsx** | `getElementById('root')` might be null | Code uses non-null assertion `!` — safe because index.html always has `<div id="root">` |

## ESLint & Code Style
- ESLint extends: `js/recommended`, `tseslint.configs.recommended`, `react-hooks`, `react-refresh`
- React Refresh used in Vite dev server (HMR for components)
- Check style before committing: `pnpm lint`

## Loading the Extension in Chrome
1. Run `pnpm build` to generate `dist/` folder
2. Open `chrome://extensions/`
3. Enable "Developer mode" (top right)
4. Click "Load unpacked" and select the project root folder
5. Chrome reads `manifest.json` and loads popup from `dist/index.html`
6. After code changes, rebuild and click "Reload" on the extension card
